### Mapping onto Stack's reset flow (checked against the installed `@stackframe/react` 2.8.48 typings and sources)
1. Request: `stackClientApp.sendForgotPasswordEmail(email, { callbackUrl? })` returns `Result<undefined, UserNotFound>`. **Treat `UserNotFound` exactly like success** (neutral "Sent" state) to avoid account enumeration.
2. Reset link target: if `callbackUrl` is omitted the SDK uses the absolute URL of `stackClientApp.urls.passwordReset` (default Stack handler page `/handler/password-reset`), resolved against the current page. To use the custom step 2 screen, either set `urls.passwordReset` to `/recuperar-palavra-passe/nova` in `src/stack.ts` or pass `callbackUrl` explicitly. Stack's email appends the one-time code as the `code` query parameter (the SDK's own reset page reads `code`; the exact placement in the email template was not verified).
3. Step 2: read `code` from the URL, call `verifyPasswordResetCode(code)` (`Result<undefined, VerificationCodeError>`); error means the "Invalid or expired link" state. Submit with `resetPassword({ code, password })`, same error type. After reading `code`, remove it from the address bar (`history.replaceState`) and send no external requests from that page, so the code cannot leak through `Referer` (Security Engineer to review).
4. Not verified (cannot be checked without the real Stack project and its dashboard): whether a custom `callbackUrl` host/path must be whitelisted in the Stack project's domain settings; the code lifetime and single-use rule; how Stack signals "too many requests" (the typings declare no specific error, so the rate-limited state is a prepared copy awaiting a confirmed signal); whether a successful reset signs the user in or revokes other sessions (design assumes neither: the user goes to Login).
5. Touches authentication: needs the `authentication-authorization` skill and a Security Engineer review before implementation. Until approved the interim hosted-page link stays.

### Terms consent (server-side)
Contract read from `docs/api/auth-contract.md` section 7 **[backend contract]**: `GET /me/consent` returns `{ currentTermsVersion, accepted, acceptedVersion, acceptedAt }`; `POST /me/consent` with `{ termsVersion }` returns 201 first time or 200 when already recorded, `{ termsVersion, acceptedAt }`; 400 for a missing, empty or non-current version; 401; 409 when the user's profile row is not yet synced; 429 rate limit. The client sends exactly the version string read from `GET`, never a timestamp, and shows no server text. Calls go through `lib/apiClient.ts` (the only place that sets the Bearer token).
- Credentials sign-up: Registar validates the terms checkbox, leaves a short-lived **hint** in `sessionStorage` (`pm.consentHint`, a timestamp only, 15 min, cleared on failure and on Login), signs up and navigates to Home. The gate then reads the version from `GET /me/consent` and records it with `POST`. This deviates from "record in Register" on purpose: Stack's session change makes `RedirectIfSignedIn` unmount Register immediately, so a retry state could not live there; the outcome is the same and the server stays the authority.
- Google sign-up: the checkbox must be ticked first; the hint is left before the OAuth redirect; after the return (to `/`) the gate records it.
- Failures after account creation: 409 is retried automatically up to 3 times (1.5 s apart), then a clear retry state "A tua conta ainda está a ser configurada..."; 429 and other errors show a retry state; the page is never shown silently without consent. 400 (version changed) restarts the check with the new version and asks the user.
- **Consent gate [engineer proposal, not in Figma]:** wraps Home and Álbuns for signed-in users. If the server says the current version is not accepted and there is no hint (accounts created before this feature, a new terms version, or storage unavailable) it shows "Antes de continuares" with the terms checkbox, "Aceitar e continuar" and "Terminar sessão". While checking it shows a status panel; if the check fails, a retry panel. Not enforced by the backend yet (contract: other endpoints do not reject users without consent).
- The terms checkbox label is plain text: **no Terms or Privacy page or text exists**; no links were invented.
